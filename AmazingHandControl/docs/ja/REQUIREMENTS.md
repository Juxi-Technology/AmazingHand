# AmazingHandGUI — 要件と受け入れ基準

本書は、現在の実装から導出した機能要件と受け入れ基準を
まとめたものです。各要件は、その動作が実装されている
ソースファイルを参照しています。

---

## 1. 接続管理

### FR-CONN-1: シリアルポートの選択
GUI は、自動検出したシリアルポートを一覧表示するコンボボックスを提供します。

| AC | 基準 |
|----|-----------|
| 1.1 | Linux では `/dev/ttyACM*`、`/dev/ttyUSB*`、`/dev/ttyAMA*` デバイスが表示される。存在しない場合は、フォールバックとして `/dev/ttyACM0` と `/dev/ttyUSB0` が一覧表示される。 |
| 1.2 | Windows では `COM1`–`COM20` が一覧表示される。 |
| 1.3 | 既定値は `config.yaml` のプラットフォーム固有の値（`/dev/ttyACM0` または `COM9`）と一致する。 |

### FR-CONN-2: ボーレートの選択
コンボボックスが設定可能なボーレートの選択肢を提供します。

| AC | 基準 |
|----|-----------|
| 2.1 | 選択肢は `config.yaml` → `serial.baudrate_options` から取得する（既定 `[9600, 115200, 1000000]`）。 |
| 2.2 | 既定の選択は `1000000`。 |
| 2.3 | 接続中はドロップダウンが無効化される。 |

### FR-CONN-3: 接続 / 切断
Connect ボタンと Disconnect ボタンは、シリアル接続とサーボトルクを管理します。

| AC | 基準 |
|----|-----------|
| 3.1 | Connect はシリアルポートを開き、サーボ 1–8 のトルクを有効にし、Connect/ポート/ボーレートのコントロールを無効化し、Disconnect を有効化する。 |
| 3.2 | Disconnect は 8 個すべてのサーボのトルクを無効にし、Connect/ポート/ボーレートを再度有効化し、Disconnect を無効化する。 |
| 3.3 | 接続に失敗すると、ステータスバーとログにエラーが表示され、GUI は未接続のままとなる。 |

### FR-CONN-4: 起動時の自動接続
GUI は起動から 100 ms 後に自動接続を試みます。

| AC | 基準 |
|----|-----------|
| 4.1 | 初期化時に `root.after(100, …)` を介して `connect_controller()` が呼び出される。 |

### FR-CONN-5: CLI の接続
CLI は `--port` および `--baudrate` 引数を介して接続します。

| AC | 基準 |
|----|-----------|
| 5.1 | `--port` と `--baudrate` は既定値を上書きする。 |
| 5.2 | 接続時に 8 個すべてのサーボのトルクが有効化される。 |
| 5.3 | 終了時にトルクが無効化される（`finally` ブロックにより Ctrl+C の場合も含む）。 |
| 5.4 | `--list` はハードウェア接続を**開きません**。 |

## 2. 指の制御

### FR-FING-1: 4 つの指ウィジェット
薬指、中指、人差し指、親指の 4 つの指コントロールが表示され、それぞれに 2 つのサーボがあります。

| AC | 基準 |
|----|-----------|
| 1.1 | ちょうど 4 つの `FingerControl` ウィジェットが、`config.yaml` のサーボペアに一致する名前で描画される：薬指 (5,6)、中指 (3,4)、人差し指 (1,2)、親指 (7,8)。 |

### FR-FING-2: Auto モード（Base + Side）
Auto モードは、垂直の開閉スライダーと水平の左右スライダーを提供します。

| AC | 基準 |
|----|-----------|
| 2.1 | 垂直スライダー：0°（開く）〜110°（閉じる）。上 = 閉じる、下 = 開く。 |
| 2.2 | 水平スライダー：−40° 〜 +40°。 |
| 2.3 | どちらのスライダーを動かしても、補間された位置が（`compute_auto_positions` を介して）両方のサーボへ送信される。 |

### FR-FING-3: Raw モード
Raw モードは、2 つの独立した垂直スライダー（サーボごとに 1 つ）を表示します。

| AC | 基準 |
|----|-----------|
| 3.1 | Raw を選択すると Auto スライダーが非表示になり、サーボごとに 2 つの垂直スライダー（−40 〜 110）が表示される。 |
| 3.2 | Mimic チェックボックスは無効化され、チェックが外れる。Center ボタンは無効化される。 |
| 3.3 | モードを切り替えると値が双方向に同期される（`decompose_servo_positions` を介して auto ↔ raw）。 |

### FR-FING-4: 速度制御
各指には速度コンボボックス（1–6）があります。

| AC | 基準 |
|----|-----------|
| 4.1 | 範囲は `speeds.min`（1）〜`speeds.max`（6）、既定は `speeds.default`（3）。 |
| 4.2 | 速度は位置コマンドの前に、サーボごとに `write_goal_speed()` を介して送信される。 |

### FR-FING-5: Mimic モード
Mimic を有効にした指の開閉変化は、Mimic が有効な他のすべての指に伝播されます。

| AC | 基準 |
|----|-----------|
| 5.1 | A と B で Mimic を有効にすると、A の開閉スライダーの変化が B に反映され、その逆も同様となる。 |
| 5.2 | Mimic は Auto モードでのみ適用される。Raw に切り替えると無効化される。 |

### FR-FING-6: Center ボタン
左右オフセットを 0° にリセットします。

| AC | 基準 |
|----|-----------|
| 6.1 | Center をクリックすると `side_var` が 0 に設定され、位置更新がトリガーされる。 |
| 6.2 | Raw モードでは Center が無効化される。 |

### FR-FING-7: 位置スライダーのマウスホイール
スクロールホイールで位置を ±5° 調整します。

| AC | 基準 |
|----|-----------|
| 7.1 | スクロールアップ → +5°（閉じる）、スクロールダウン → −5°（開く）、限界値でクランプされる。 |

### FR-FING-8: LED アクティビティインジケーター
各指はステータス LED を表示します。

| AC | 基準 |
|----|-----------|
| 8.1 | 動作中（moving フラグ = true）→ 約 350 ms 間隔で緑に点滅。 |
| 8.2 | ブロック（目標と位置の誤差 ≥ 8° かつ非動作）→ 赤の点灯。 |
| 8.3 | アイドル → グレー。 |

## 3. キーボード制御

### FR-KEY-1: 指の選択
キー 1–4 でアクティブな指を選択します。

| AC | 基準 |
|----|-----------|
| 1.1 | 1 = 薬指、2 = 中指、3 = 人差し指、4 = 親指。 |
| 1.2 | ステータスバーに選択した指の名前が表示される。 |

### FR-KEY-2: 矢印キーでの移動
矢印キーで選択した指を動かします。

| AC | 基準 |
|----|-----------|
| 2.1 | 上 = 閉じる（位置を増加）、下 = 開く（減少）。 |
| 2.2 | 右 = 左右オフセットを増加、左 = 減少。 |

### FR-KEY-3: 精度修飾キー
ステップ幅は修飾キーによって変わります。

| AC | 基準 |
|----|-----------|
| 3.1 | 修飾キーなし：1°（精密）。 |
| 3.2 | Shift：5°（通常）。 |
| 3.3 | Ctrl：10°（高速）。 |
| 3.4 | ステータスバーにモード名と結果の角度が表示される。 |

### FR-KEY-4: クイック操作
よく使う操作のための単一キーショートカット。

| AC | 基準 |
|----|-----------|
| 4.1 | Q = 110° まで完全に閉じる。 |
| 4.2 | E = 0° まで完全に開く。 |
| 4.3 | C = 左右を 0° にセンタリング。 |

## 4. グローバルコントロール

### FR-GLOB-1: Open All
すべての指を完全に開いた状態に設定します。

| AC | 基準 |
|----|-----------|
| 1.1 | すべての `pos_var` → 0、すべての `side_var` → 0、位置がハードウェアへ送信される。 |

### FR-GLOB-2: Close All
すべての指を完全に閉じた状態に設定します。

| AC | 基準 |
|----|-----------|
| 2.1 | すべての `pos_var` → 110、すべての `side_var` → 0、位置が送信される。 |

### FR-GLOB-3: Center All
すべての左右オフセットをリセットします。

| AC | 基準 |
|----|-----------|
| 3.1 | すべての `side_var` → 0、位置が送信される。 |

### FR-GLOB-4: グローバル速度
ドロップダウンで全指の速度をまとめて設定します。

| AC | 基準 |
|----|-----------|
| 4.1 | 値を選択すると、すべての指の速度コンボボックスが更新される。 |
| 4.2 | 速度は [1, 6] にクランプされる。 |

## 5. ポーズ管理

### FR-POSE-1: ポーズの保存
ユーザーが名前を入力し、現在の 8 サーボの位置を保存します。

| AC | 基準 |
|----|-----------|
| 1.1 | 4 本すべての指の位置（8 値）が `get_positions()` を介して取得される。 |
| 1.2 | 保存前に `validate_name()` を介して名前が検証される。 |
| 1.3 | 成功時：ドロップダウンが更新され（ソート済み）、入力欄がクリアされ、ステータスバーが確認を表示する。 |
| 1.4 | 無効または空の名前は、エラーメッセージボックスを表示する。 |

### FR-POSE-2: ポーズの適用
ポーズを選択して Apply をクリックすると、ハンドがそのポーズへ移動します。

| AC | 基準 |
|----|-----------|
| 2.1 | 8 つの位置がすべての指ウィジェットに適用される。 |
| 2.2 | サーボ位置がハードウェアへ送信される。 |
| 2.3 | 遅延は移動距離と速度から見積もられる。その遅延後に、目標と実際の比較とともにポーズ完了がログに記録される。 |

### FR-POSE-3: ポーズの削除
確認後、選択したポーズを削除します。

| AC | 基準 |
|----|-----------|
| 3.1 | はい/いいえのメッセージボックスで確認を求める。 |
| 3.2 | 確認時：ポーズが設定から削除され、YAML が保存され、ドロップダウンが更新される。 |
| 3.3 | ポーズが残っていない場合、ドロップダウンは `<no poses>` を表示する。 |

### FR-POSE-4: 名前の検証
YAML の破損を防ぐため、名前が検証されます。

| AC | 基準 |
|----|-----------|
| 4.1 | 空 / 空白のみ → 拒否される。 |
| 4.2 | 50 文字を超える → 拒否される。 |
| 4.3 | `: { } [ ] , & * # ? \| - < > = ! % @ \` " '` を含む → 拒否される。 |
| 4.4 | 制御文字（ASCII < 32）を含む → 拒否される。 |
| 4.5 | 先頭/末尾の空白 → 拒否される。 |

## 6. シーケンス管理

### FR-SEQ-1: シーケンスプレイヤー（メインウィンドウ）
ドロップダウン選択、Loop チェックボックス、Play / Pause / Stop ボタン。

| AC | 基準 |
|----|-----------|
| 1.1 | ドロップダウンに保存されたすべてのシーケンス（または `<no sequences>`）が一覧表示される。 |
| 1.2 | Loop チェックボックスで連続リピートが有効になる。 |
| 1.3 | Play はバックグラウンドスレッドでシーケンスを開始する。 |
| 1.4 | Pause は一時停止/再開を切り替える。ボタンのテキストは「⏸ Pause」と「▶ Resume」の間で切り替わる。 |
| 1.5 | Stop は `stop_sequence = True` を設定し、シーケンススレッドが終了する。 |

### FR-SEQ-2: シーケンス実行エンジン
シーケンスは割り込み可能なスリープを伴うバックグラウンドスレッドで実行されます。

| AC | 基準 |
|----|-----------|
| 2.1 | ポーズステップは `"pose_name:s1,s2,...,s8\|delay"` 形式を解析する。 |
| 2.2 | `SLEEP:duration` ステップは、ハードウェアコマンドなしで一時停止する。 |
| 2.3 | 明示的な遅延がない場合：自動待機 = `15.0 − (avg_speed − 1) × 2.4` 秒。 |
| 2.4 | スリープは 0.1 s 刻みで実行され、各ティックで停止/一時停止フラグを確認する。 |
| 2.5 | ループモードでは、各反復の間に 0.5 s の間隔が入る。 |
| 2.6 | 不明なポーズ名は警告とともにスキップされる。 |
| 2.7 | 実行中は Play/Pause/Stop ボタンが有効/無効の状態を切り替える。 |

### FR-SEQ-3: シーケンスマネージャーダイアログ
「🔧 Manage」ボタンからアクセスする 2 パネルのダイアログ。

| AC | 基準 |
|----|-----------|
| 3.1 | 左パネル：保存されたシーケンスのリストボックスと、Execute、Edit、Delete ボタン。 |
| 3.2 | ダブルクリックすると、ダイアログを閉じずにシーケンスを 1 回実行する（ループなし）。 |
| 3.3 | Edit はステップをビルダーに読み込み、名前欄をあらかじめ埋める。 |

### FR-SEQ-4: シーケンスビルダー
ポーズからシーケンスを構築するための右パネル。

| AC | 基準 |
|----|-----------|
| 4.1 | 使用可能なポーズが一覧表示される。ダブルクリックで現在の速度/遅延を伴うステップが追加される。 |
| 4.2 | 指ごとの速度スピンボックス（1–6）。「⬇ Copy from UI」でメインウィンドウの速度を取り込む。 |
| 4.3 | 遅延の入力は、ポーズステップに `\|delay` 接尾辞を付加する。 |
| 4.4 | 「⏱ Delay」は単独の `SLEEP:Xs` ステップを挿入する。 |
| 4.5 | ↑/↓ で並べ替え、➖ で削除、🗑 で全消去。 |
| 4.6 | 「💾 Save Sequence」は名前を検証し、保存し、ドロップダウンを更新する。 |
| 4.7 | 「▶ Execute」は、保存もダイアログの閉じも行わずに、構築したシーケンスを実行する。 |

### FR-SEQ-5: 遅延入力の検証
遅延入力の無効な浮動小数点値は、適切に処理されます。

| AC | 基準 |
|----|-----------|
| 5.1 | 数値でない遅延は遅延なしを既定とする（`\|delay` なしでステップが追加される）。 |
| 5.2 | 数値でない SLEEP 遅延は、ステータスバーに「Invalid delay value」を表示する。 |

## 7. サーボ監視

### FR-MON-1: バックグラウンドのテレメトリ収集
デーモンスレッドが 8 個すべてのサーボを約 10 Hz でポーリングします。

| AC | 基準 |
|----|-----------|
| 1.1 | スレッドは各反復の間に 0.1 s スリープする。 |
| 1.2 | サーボごとに収集する指標：位置、負荷、温度、電圧、速度、moving フラグ、ステータス、目標。 |
| 1.3 | 読み取りに失敗した場合は、配列の同期を保つため最後に判明した値を繰り返す。 |
| 1.4 | フィードバックデータは `feedback_lock` の下でアトミックに更新される。 |

### FR-MON-2: グラフ表示
右パネルに埋め込まれた Matplotlib グラフ。

| AC | 基準 |
|----|-----------|
| 2.1 | 選択可能な指標：位置、目標 vs 現在、トルク、速度、温度、電圧、動作中。 |
| 2.2 | 「Servos」ドロップダウンで 8 本のトレースの表示/非表示を切り替える（✓ All / ✕ None 付き）。 |
| 2.3 | グラフの再描画は 100 ms 以上間隔でスロットリングされる。 |
| 2.4 | 指標が未選択 → 「Select at least one metric」メッセージ。 |
| 2.5 | データなし → 「Waiting for data...」メッセージ。 |

### FR-MON-3: グラフモード
2 つのモード：Multi-Servo と Scope。

| AC | 基準 |
|----|-----------|
| 3.1 | Scope モードは、単一のサーボに注目するための「Scope Servo」セレクターを表示する。 |
| 3.2 | Multi-Servo は Scope Servo セレクターを非表示にする。 |

### FR-MON-4: グラフのズームとパン
表示を制御する 4 つのスライダー。

| AC | 基準 |
|----|-----------|
| 4.1 | Y-Zoom：0.2× 〜 5.0×、既定 1.1×。 |
| 4.2 | Y-Pan：−3.0 〜 +3.0、既定 0.0。 |
| 4.3 | Time-Zoom：利用可能なデータの 10 % 〜 100 %。 |
| 4.4 | Time-Pan：0 %（最も古い）〜 100 %（最新）。 |
| 4.5 | すべてのスライダーはデバウンスされたグラフ再描画をトリガーする。 |

### FR-MON-5: ローリングモード
グラフを最新の N データ点に限定します。

| AC | 基準 |
|----|-----------|
| 5.1 | 有効かつデータが `max_data_points`（100）を超える場合、最も古いサンプルが破棄される。 |
| 5.2 | ローリングを無効にすると、収集したすべてのデータが保持される。 |

### FR-MON-6: グラフの一時停止 / 再開 / クリア

| AC | 基準 |
|----|-----------|
| 6.1 | Pause はグラフの再描画を停止するが、テレメトリ収集は継続する。 |
| 6.2 | Clear はすべてのデータ配列とズーム/パンを既定値にリセットする。 |

### FR-MON-7: フィードバックパネル
すべてのサーボのライブテレメトリを表示するグリッドテーブル。

| AC | 基準 |
|----|-----------|
| 7.1 | 列：S1–S8。行：目標、位置、速度、トルク、電圧、電流、温度、ステータス、動作中。 |
| 7.2 | 値は `format_feedback_value()` によって整形される：位置 `X.XX°`、速度 `X.X°/s`、電圧 `X.XX V`、温度 `X.X °C`、電流 `X mA`、負荷 `X.X %`、ステータス `0xHH`、動作中 `Yes/No`。 |
| 7.3 | 変更されたセルのみが更新される（差分キャッシュ）。 |
| 7.4 | 更新間隔は 50 ms 以上にスロットリングされる。 |

## 8. 設定

### FR-CFG-1: アプリ設定の読み込み
`config.yaml` は、欠落したすべてのキーに既定値を用いて読み込まれます。

| AC | 基準 |
|----|-----------|
| 1.1 | ファイル欠落 → 完全な既定設定が使用される。 |
| 1.2 | 欠落したキーは既定値からマージされる（2 段階マージ）。 |
| 1.3 | 解析失敗 → 既定値が返され、エラーが stdout に出力される。 |

### FR-CFG-2: サーボマッピング
指ごとのサーボ ID は `config.yaml` → `servos` で定義されます。

| AC | 基準 |
|----|-----------|
| 2.1 | 設定は pointer=[1,2]、middle=[3,4]、ring=[5,6]、thumb=[7,8] を定義する。 |
| 2.2 | `all_ids` = [1,2,3,4,5,6,7,8]。 |

### FR-CFG-3: 角度限界

| AC | 基準 |
|----|-----------|
| 3.1 | `servo_min` = −40、`servo_max` = 110、`base_min` = 0、`base_max` = 110、`side_min` = −40、`side_max` = 40。 |
| 3.2 | すべてのスライダー範囲はこれらの値から導出される。 |

### FR-CFG-4: Auto Extremes
左右オフセット計算のための双一次補間の端点。

| AC | 基準 |
|----|-----------|
| 4.1 | `left_open`、`right_open`、`left_closed`、`right_closed`、`center_open`、`center_closed` は設定可能。 |
| 4.2 | `compute_auto_positions()` は補間のためにこれらを使用する。 |

### FR-CFG-5: 速度設定

| AC | 基準 |
|----|-----------|
| 5.1 | `speeds.default` = 3、`speeds.min` = 1、`speeds.max` = 6。 |

## 9. CLI ツール

### FR-CLI-1: ポーズとシーケンスの一覧表示
`--list` は接続を開かずに、すべてのポーズとシーケンスを出力します。

| AC | 基準 |
|----|-----------|
| 1.1 | 出力にポーズ数と、各名前と位置が表示される。 |
| 1.2 | 出力にシーケンス数と、各名前とステップ数および詳細が表示される。 |
| 1.3 | シリアル接続は開かれない。 |

### FR-CLI-2: ポーズの適用
`--pose NAME` は保存されたポーズをハードウェアへ送信します。

| AC | 基準 |
|----|-----------|
| 2.1 | 位置は設定から読み込まれ、既定速度 3 がすべてのサーボに適用される。 |
| 2.2 | 不明なポーズ → エラー + `sys.exit(1)`。 |

### FR-CLI-3: シーケンスの再生
`--sequence NAME` はシーケンスを再生し、`--loop` は Ctrl+C まで繰り返します。

| AC | 基準 |
|----|-----------|
| 3.1 | 速度と遅延はステップ文字列から解析される。 |
| 3.2 | `SLEEP` ステップは、ハードウェアコマンドなしで一時停止する。 |
| 3.3 | 明示的な遅延がない場合 → 自動待機 = `15.0 − (avg_speed − 1) × 2.4` 秒。 |
| 3.4 | SIGINT は `stop_flag` を設定して、優雅に割り込む。 |
| 3.5 | 不明なシーケンス → エラーで終了。 |
| 3.6 | 空のシーケンス → エラーで終了。 |
| 3.7 | シーケンス内の不明なポーズは WARNING とともにスキップされる。 |

### FR-CLI-4: ステップの解析
`parse_step()` は複数の形式を処理します。

| AC | 基準 |
|----|-----------|
| 4.1 | `SLEEP:2.0s` → 2.0 s のスリープ。 |
| 4.2 | `open:3,3,...\|2.0s` → 速度と 2.0 s の遅延を伴うポーズ「open」。 |
| 4.3 | `open`（裸の名前）→ 既定速度・遅延なしのポーズ。 |
| 4.4 | 速度が 8 個未満の場合は 3 で埋められ、それより長い場合は切り捨てられる。 |
| 4.5 | 時間の接尾辞 `s` / `S` は取り除かれる。 |

### FR-CLI-5: 相互排他的な操作
`--list`、`--pose`、`--sequence` は相互に排他的です。

| AC | 基準 |
|----|-----------|
| 5.1 | 複数の操作を渡す → 非ゼロで終了。 |
| 5.2 | `--sequence` なしの `--loop` → エラー。 |

### FR-CLI-6: 設定ファイルの上書き
`--config PATH` は代替の YAML ファイルを使用します。

| AC | 基準 |
|----|-----------|
| 6.1 | ファイル欠落 → エラー + `sys.exit(1)`。 |

## 10. データの永続化

### FR-DATA-1: YAML 設定ファイル
ポーズとシーケンスは `data/hand_config.yaml` に保存されます。

| AC | 基準 |
|----|-----------|
| 1.1 | ファイルは `poses` と `sequences` をトップレベルキーとする YAML 形式を使用する。 |

### FR-DATA-2: 設定の読み込み

| AC | 基準 |
|----|-----------|
| 2.1 | ファイル欠落 → `{'poses': {}, 'sequences': {}}`。 |
| 2.2 | 空のファイル → キーが自動的に設定される。 |
| 2.3 | 不正な YAML → 空の構造、エラーが stdout に出力される。 |

### FR-DATA-3: インライン配列での設定の保存
位置は正規表現による後処理を介してフロースタイルで保存されます。

| AC | 基準 |
|----|-----------|
| 3.1 | ファイルに `positions: [v1, v2, …, v8]` 形式が含まれる。 |
| 3.2 | 負の値はインライン形式で保持される。 |
| 3.3 | 成功時は `True`、エラー時は `False` を返す。 |

### FR-DATA-4: データディレクトリの自動作成

| AC | 基準 |
|----|-----------|
| 4.1 | 書き込み前に、`data/` ディレクトリが存在しない場合は作成される。 |

### FR-DATA-5: 往復の整合性
GUI が書き込んだデータは CLI で読み取ることができ、その逆も同様です。

| AC | 基準 |
|----|-----------|
| 5.1 | ポーズ、負の位置、シーケンスステップは、GUI 保存 → CLI 読み取りの往復を経ても保持される。 |

## 11. エラー処理

### FR-ERR-1: 接続エラー
接続に失敗してもアプリケーションはクラッシュしません。

| AC | 基準 |
|----|-----------|
| 1.1 | ステータスバーに「Connection failed: …」を表示し、`connected` は `False` のまま。 |

### FR-ERR-2: 無効なボーレート

| AC | 基準 |
|----|-----------|
| 2.1 | 数値でないボーレート → ステータスバーに「Invalid baudrate」を表示。 |

### FR-ERR-3: 監視スレッドのリカバリ

| AC | 基準 |
|----|-----------|
| 3.1 | 単一のサーボ読み取り失敗でスレッドはクラッシュしない。 |
| 3.2 | エラーは stdout に出力される。 |

### FR-ERR-4: moving フラグの縮退

| AC | 基準 |
|----|-----------|
| 4.1 | `read_moving` が 3 回連続で失敗すると、監視がログメッセージとともに無効化される。 |
| 4.2 | 最初の同期失敗時に `sync_read_moving` からサーボ単位の読み取りへフォールバックする。 |

### FR-ERR-5: ポーズ完了の警告

| AC | 基準 |
|----|-----------|
| 5.1 | 目標と実際の誤差 > 5° で、ログに ⚠ 警告が出力される。 |
| 5.2 | 動作タイムアウト（6.0 s）は、サーボが動作を停止しない場合にタイムアウト警告をトリガーする。 |

### FR-ERR-6: 設定の欠落（CLI）

| AC | 基準 |
|----|-----------|
| 6.1 | 設定ファイル欠落 → エラーメッセージ + `sys.exit(1)`。 |

### FR-ERR-7: 空 / 無効なシーケンス

| AC | 基準 |
|----|-----------|
| 7.1 | 空のシーケンスステップ → `sys.exit(1)`。 |
| 7.2 | シーケンス内の不明なポーズ → WARNING とともにスキップ。 |
