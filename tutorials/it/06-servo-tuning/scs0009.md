# Messa a punto e calibrazione dei servo SCS0009

La versione SCS0009 prevede due tipi di messa a punto:

1. **Assemblaggio e messa a punto della posizione centrale TTL**: cablaggio, impostazione dell'ID del servo, fissaggio del braccio, regolazione fine della posizione centrale, esecuzione dei test.
2. **Strumento di debug SCS0009**: GUI Python + PySide6, scansione del bus, lettura/scrittura di tutti i registri, controllo di posizione, baudrate/ripristino di fabbrica, backup xdat della EEPROM.

> Per i dettagli dei registri del protocollo vedi [Tabella di memoria del protocollo SCS0009](../../../AmazingHandControl/docs/zh-hans/scs_servo_protocol.md).
> Per il cablaggio Arduino/estensione vedi [Arduino Nano](../07-arduino/arduino-nano.md).

## 1. Messa a punto TTL: assemblaggio, ID e posizione centrale

Per prima cosa scarica l'archivio [灵巧手调试.zip](https://juxitech.feishu.cn/wiki/QjYBwL0A0iJVlNkEpUUclLYGnBc); dopo l'estrazione puoi seguire il documento «Processo di debug della mano robotica con il programma Arduino (servo TTL)» per impostare l'ID dei servo, calibrare, regolare la posizione centrale ed eseguire il programma dimostrativo, oppure fare riferimento al [codice open source ufficiale](https://github.com/pollen-robotics/AmazingHand/tree/main/ArduinoExample).

**Nel caso di prodotto finito e non smontato** (ID dei servo, calibrazione e posizione centrale sono già regolati in fabbrica) puoi passare direttamente al [punto 6 Esecuzione del «programma dimostrativo 02»](#6-esecuzione-del-programma-dimostrativo-02) e al [tracciamento delle mani](../05-hand-tracking/scs0009.md).

## 2. Strumento di debug SCS0009

Compatibile con Windows 10 / 11; per le differenze su Linux e macOS vedi [sezione 8](#8-differenze-linux-e-macos). Questo tutorial copre ogni passaggio, dall'installazione dell'ambiente alla messa a punto completa.

> ⚠️ **Nota di compatibilità: questo strumento supporta attualmente solo i servo Feetech SCS0009** (serie SCS, retroazione di posizione a potenziometro, risoluzione a 10 bit 0–1023). La tabella dei registri e il formato dei parametri xdat sono progettati per lo Feetech SCS0009; altri marchi/modelli non sono garantiti compatibili.

### 1. Requisiti dell'ambiente

| Dipendenza | Versione | Descrizione |
|------|------|------|
| Python | >= 3.8 | Si consiglia 3.10+, scaricalo da [python.org](https://www.python.org/downloads/) |
| PySide6 | >= 6.0 | Framework della GUI |
| pyserial | >= 3.5 | Comunicazione seriale |
| Sistema | Win10 / Win11 | Qualsiasi versione |

### 2. Installazione di Python

1. Vai su <https://www.python.org/downloads/>
2. Scarica il pacchetto di installazione Python 3.10+
3. Durante l'installazione **assicurati di selezionare "Add Python to PATH"** (altrimenti la riga di comando non trova python)

Verifica dell'installazione:

```bash
python --version
```

### 3. Installazione delle dipendenze

Si consiglia di installare in un ambiente virtuale per non inquinare il Python di sistema:

```bash
# entra nella directory del progetto
cd SCS0009_ServoController

# crea l'ambiente virtuale
python -m venv .venv

# attiva l'ambiente virtuale (Windows)
.venv\Scripts\activate

# installa le dipendenze
pip install -r requirements.txt
```

> ⚠️ **L'ambiente virtuale va creato una sola volta**. Eseguirlo di nuovo sovrascrive l'ambiente originale (cancellando le dipendenze installate). In seguito basta solo `activate`.

> Suggerimento: dopo l'attivazione il prefisso della riga di comando mostra `(.venv)`.

### 4. Verifica dell'ambiente

```bash
python setup.py
```

Se compare `[OK] 环境检查通过，可以运行项目` l'ambiente è corretto.

### 5. Collegamento dell'hardware

1. Inserisci l'adattatore USB-seriale (ad es. CH340 / CP2102) nel PC
2. Collega il controller del servo (scheda di controllo del braccio robotico)
3. Alimenta i servo (si consiglia DC 5V 5A, versione Pro DC 12V 5A)

Apri Gestione dispositivi (`Win+X` → Gestione dispositivi) e verifica il numero di porta:

```
端口 (COM 和 LPT)
  └─ USB-SERIAL CH340 (COM3)     ← 你的舵机串口
```

> **Annota il numero COM**, da selezionare all'avvio del programma.

### 6. Avvio della GUI

```bash
python -m src.gui.factory_calibration_tool
```

Oppure specifica manualmente la porta (quando la seriale è occupata):

```bash
python -m src.gui.factory_calibration_tool --port COM3
```

Visualizza le porte disponibili:

```bash
python -m src.gui.factory_calibration_tool --list-ports
```

### 7. Flusso operativo dell'interfaccia

> L'interfaccia ha un layout a pannello singolo; quando l'altezza della finestra non è sufficiente compare automaticamente una barra di scorrimento, e a schermo massimizzato si adatta in modo elastico.

#### 7.1 Connessione seriale

- Seleziona porta e baudrate (predefinito 1M), fai clic su **Connetti**
- Lo stato mostra `🟢 已连接`

#### 7.2 Scansione dei servo

- Fai clic su **Scansiona servo**, rileva i servo online con ID 1-254
- I risultati della scansione vengono mostrati in tempo reale nell'elenco dei servo (con il modello)
- Fai clic su una riga dell'elenco dei servo → viene compilato automaticamente nel menu a tendina dei servo

#### 7.3 Lettura/scrittura dei parametri

- **Leggi parametri**: legge tutti i 44 registri (EEPROM + SRAM), il log mostra i risultati in tempo reale
- **Tabella dei parametri**: visualizzazione a 5 colonne (indirizzo/registro/valore/area di memoria/lettura-scrittura), con colori distinti per EEPROM/SRAM/DEFAULT
- **Selezione collegata**: fai clic su una riga della tabella → compila automaticamente "indirizzo di scrittura", "lunghezza", "valore"
- **Scrittura**: dopo aver modificato il valore fai clic su scrivi; il programma sblocca/scrive/blocca automaticamente
- **Finestra del risultato di scrittura**: in caso di successo compare un avviso verde "✅ 已成功写入", in caso di errore un avviso rosso "❌ 写入失败" (con la causa)

#### 7.4 Modifica dell'ID del servo

1. **Collega al bus solo il servo di cui vuoi cambiare l'ID**, per evitare conflitti con ID già esistenti.
2. Nella tabella dei parametri individua e seleziona la riga «ID servo» (indirizzo `0x05`).
3. Cambia il "valore" nell'ID target e fai clic su **✏️ Scrivi**; il programma sblocca → scrive → riblocca automaticamente.
4. Dopo la modifica riesegui la scansione del bus per confermare. Mano destra 1–8, mano sinistra 11–18.

#### 7.5 Controllo di posizione

1. Trascina lo slider o inserisci direttamente la posizione target (0–1023); il campo numerico è sincronizzato con lo slider.
2. Fai clic su **▶ Muovi**, la barra di stato mostra «in movimento…».
3. Al raggiungimento della posizione compare «movimento completato, chiudi la coppia»; fai clic su **⏹ Coppia off**.

#### 7.6 Baudrate/ripristino di fabbrica

- **Modifica del baudrate**: seleziona il nuovo baudrate (38400–1000000 bps) e scrivi; il programma cambia il baudrate della seriale e verifica con un ping, in caso di errore ripristina automaticamente.
- **Ripristino di fabbrica**: ripristina i valori predefiniti di fabbrica (ID=1, baudrate 1M); dopo è necessario rieseguire la scansione.

#### 7.7 Parametri xdat (salva solo la EEPROM)

1. `💾 Salva servo corrente`: salva i parametri EEPROM del servo con ID corrente in un file xdat (backup)
2. `📂 Apri xdat`: carica il file di backup
3. `📤 Ripristina parametri sul servo`: riscrive il backup sul servo

### 8. Differenze Linux e macOS

#### Linux

- **Font**: `sudo apt install fonts-noto-cjk fonts-noto-color-emoji`, altrimenti l'interfaccia in cinese può risultare vuota e le emoji appaiono come quadrati.
- **Permessi della seriale**: `sudo usermod -a -G dialout $USER`, disconnetti e riconnetti per rendere effettivo; `groups` deve contenere `dialout`. Temporaneamente puoi usare `sudo chmod 666 /dev/ttyUSB0`.
- **Nome del dispositivo**: `/dev/ttyUSB*` (CH340 / CP2102 / PL2303) oppure `/dev/ttyACM*` (seriale USB a bordo); usa `lsusb`, `dmesg | grep -i tty` per trovare il produttore.
- **Nome dispositivo fisso (opzionale)**: in `/etc/udev/rules.d/99-servo.rules` scrivi `SUBSYSTEM=="tty", ATTRS{idVendor}=="1a86", ATTRS{idProduct}=="7523", SYMLINK+="ttyServo"`, poi usa `/dev/ttyServo`.
- **Avvio**: `python -m src.gui.factory_calibration_tool --port /dev/ttyUSB0`.
- **Problemi comuni**: se `pip` segnala externally-managed-environment usa un venv oppure aggiungi `--break-system-packages`.

#### macOS

- **Python**: si consiglia di installare con Homebrew `brew install python`, non usare la vecchia versione di sistema.
- **Denominazione delle porte seriali**: usa `/dev/cu.*`, non `/dev/tty.*` (quest'ultimo può bloccarsi); `ls /dev/cu.*` per vedere.
- **Driver USB**: CH340 / CP2102 / FTDI sono per lo più senza driver; i lotti vecchi di CH340 richiedono il driver WCH, usa `system_profiler SPUSBDataType` per diagnosticare.
- **Avvio**: `python -m src.gui.factory_calibration_tool --port /dev/cu.usbserial-0001`.
- **Apple Silicon**: usa Python 3.10+ nativo, evita il vecchio Python sotto Rosetta; alla prima esecuzione, se compare "impossibile verificare lo sviluppatore", consenti in "Privacy e sicurezza".
- **Risparmio energetico**: la sospensione di macOS può disconnettere la seriale; mantieni il sistema sveglio durante le operazioni.

### 9. Note

1. **La scrittura è permanente**: dopo aver scritto i parametri nella EEPROM i valori originali vengono sovrascritti e non è possibile annullare; prima di modificare esegui un backup con xdat.
2. **Alimentazione stabile**: alimentazione insufficiente causa perdita di passi, errori di comunicazione o perdita di connessione dei servo; alimenta secondo i requisiti di [Cablaggio e alimentazione SCS0009](../01-hardware/scs0009.md).
3. **Seriale esclusiva**: la stessa porta non può essere aperta contemporaneamente da due programmi; prima dell'uso chiudi il monitor seriale, l'applicazione host e altri programmi che la occupano.
4. **Rischio nella modifica dell'ID**: collega al bus un solo servo di cui modificare l'ID; se dopo la modifica perde la connessione, prova «ripristino di fabbrica» (l'ID torna a 1).
5. **Sovratemperatura/sovratensione**: lo strumento monitora tensione e temperatura (allarme se temperatura > 60 °C); in caso di temperatura elevata persistente ferma il sistema per raffreddarlo.
6. **Hot plug**: dopo aver scollegato l'USB il programma tenta di riconnettersi; dopo averlo ricollegato fai clic su aggiorna porta.
7. **Caratteri errati nella console Windows**: se lo strumento da riga di comando mostra emoji corrotte, imposta `PYTHONIOENCODING=utf-8` e riesegui.

### 10. Domande frequenti

| Problema | Soluzione |
|------|------|
| Porta seriale non trovata | Controlla il driver in Gestione dispositivi; cambia porta USB; installa il driver CH340 |
| Porta seriale occupata | Chiudi programmi come il monitor seriale; riavvia lo strumento |
| Caratteri cinesi visualizzati come vuoti | Il sistema usa Microsoft YaHei come predefinito; se anomalo installa i font cinesi |
| I servo non vengono trovati | Controlla alimentazione/cablaggio; verifica il baudrate 1M |
| Scrittura fallita | Controlla alimentazione e connessione dei servo; verifica che il registro target sia scrivibile |
| PermissionError all'apertura della seriale | Assicurati che nessun altro processo occupi quella porta COM |
| Linux: `Permission denied: /dev/ttyUSB0` | Non sei nel gruppo `dialout`; vedi la sezione Linux sopra |
| macOS: blocco con nome seriale contenente `tty.` | Usa il dispositivo corrispondente `/dev/cu.*` |
