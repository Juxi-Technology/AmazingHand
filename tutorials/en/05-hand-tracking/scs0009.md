# SCS0009 Hand Tracking (Official dora Demo)

This page covers the official hand-tracking pipeline for the **SCS0009 bus servo version**: camera → MediaPipe → MuJoCo IK → AHControl (Rust) → SCS0009. For PWM-version tracking, see [PWM hand tracking](pwm.md).

The scripts 1 → 4 below use the **Windows one-click scripts** as an example; they are in `AmazingHand-main/Demo/Windows_Deploy_Scripts/`. For the location and differences of the Linux and macOS scripts, see [the end of this page](#linux-and-macos-differences). Run them in numerical order.

---

## Hardware preparation

| Hardware | Requirement |
|------|------|
| Dexterous hand | Right / Left / Both |
| Servo driver board | External, USB to PC |
| Power | External supply, at least 5V 4A (or use a 7–12V input as required by the driver board); USB power is not enough |
| Camera | Built-in or USB webcam |

> The model files can be viewed or downloaded at [Onshape](https://cad.onshape.com/documents/430ff184cf3dd9557aaff2be/w/e3658b7152c139971d22c688/e/d79fbb3641873de0a515037e) (including the URDF).

The hand's [MuJoCo model](https://github.com/pollen-robotics/AmazingHand/tree/main/Demo/AHSimulation/AHSimulation)

## Environment setup (Script 1)

![Windows one-click deployment script folder](../../assets/robot-arms/amazing-hand/gesture-tracking/windows.png)

**Double-click `1-Install_Env.bat`** — it automatically:

1. **Checks the MSVC build tools** (cl.exe) — required to compile Rust. If missing, it prompts you to install
Visual Studio 2022 Build Tools with the "Desktop development with C++" workload, then reopen the terminal.

2. **Installs Rust** (rustup + stable-msvc toolchain)

3. **Configures the cargo Tsinghua mirror** (`C:\Users\<your username>\.cargo\config.toml`) to speed up crate downloads

4. **Installs uv** (Python package manager)

5. **Installs dora-cli 0.5.0** (`cargo install`; the first compile takes about 10–20 minutes, be patient)

6. **Installs the dora-rs pip package** (optional; installed into the virtual environment)

> **Important**: after the script finishes, **close and reopen the terminal** so the environment variables take effect. The installation may be slow depending on your network; please be patient and do not close it midway.


### Environment setup alternative (if the scripts don't work)

- **Rust**: [https://www.rust-lang.org/tools/install](https://www.rust-lang.org/tools/install)

    - On Windows use rustup-init.exe and choose the default MSVC toolchain

    - Environment variable: add `%USERPROFILE%\.cargo\bin` to PATH

- **uv**: in PowerShell run `irm https://astral.sh/uv/install.ps1 | iex`.

    - Environment variable: add `%USERPROFILE%\.local\bin` to PATH

- **dora-cli**: `cargo install dora-cli --version 0.5.0`

### cargo Tsinghua mirror settings (~/.cargo/config.toml)

```bash
[source.crates-io]
replace-with = "tuna"

[source.tuna]
registry = "sparse+https://mirrors.tuna.tsinghua.edu.cn/crates.io-index/"

[registries.tuna]
index = "sparse+https://mirrors.tuna.tsinghua.edu.cn/crates.io-index/"

[http]
check-revoke = false
```

> Use the **sparse index** (as above), not the git-repo mirror — the git method first downloads about 1 GB of index and easily hangs at `Updating 'tuna' index`.

## Wiring

- Connect the servo driver board to the PC via USB, with an **external power supply** (at least 5V 4A, or use a 7–12V input as required by the driver board)

- Find the port on the PC: **Device Manager → Ports (COM & LPT)**, e.g. `COM11`

## Configuring the serial port (Script 2)

**Double-click `2-Setup_Serial.bat`** (the actual logic is in `2-Setup_Serial.ps1`):

1. It prompts "connect the servo driver board to the computer" → press Enter to start detection

2. The detected COM ports are listed automatically (with device names)

3. With a single port, press Enter to confirm; with multiple ports, type the number

4. It automatically writes `--serialport` into the 3 dataflow yml files and the default port into `AHControl\src\main.rs`

5. The original files are automatically backed up as `.bak`

> If you replug the USB cable, the port number may change, so re-run this script.

## Code deployment (Script 3)

**Double-click `3-Deploy_Demo.bat`** — it automatically:

1. Starts the dora daemon (`dora up`)

2. Creates a Python 3.12 virtual environment (`uv venv --python 3.12`)

3. Activates the virtual environment

4. Builds the AHControl Rust node (`cargo build --release`, about 10 minutes the first time)

5. Syncs the AHSimulation and HandTracking dependencies (`uv sync`)

6. Force-installs mediapipe==0.10.14

> Deployment only needs to be done once. Re-running it asks whether to rebuild the virtual environment.


---

## Running the code (Script 4)

**Double-click `4-Run_Demo.bat`** — an interactive menu appears:

```bash
============================================
   Select a run mode:
============================================
    1 - Simulation (webcam hand tracking)
    2 - Real hardware
    q - Quit
============================================
  Enter number [1/2/q]:
```

- Choose **1**: simulation environment; camera gestures drive the two simulated hands

- Choose **2**: a submenu appears; choose right hand / left hand / both hands

```bash
============================================
   Real hardware - select the hand:
============================================
    1 - Right hand
    2 - Left hand
    3 - Both hands
    b - Back to main menu
============================================
```

After choosing, it automatically runs `dora build` + `dora run`. A camera window opens; make hand gestures toward the camera and the dexterous hand follows in real time. **Ctrl+C stops it**; after the dataflow ends, press Enter to return to the main menu, where you can choose another mode or press `q` to quit.

> On first run, Windows may block camera permission; click "Allow".

## Project cleanup (Script 0)

**Double-click `0-Cleanup_Project.bat`**, type `Y` to confirm, and it automatically:

1. Stops the dora daemon

2. Deletes the 3 virtual environments (`.venv`)

3. Deletes the Rust build output (`AmazingHand-main/Demo/target`)

4. Deletes `pycache`, `.bak` backups, logs, and `AmazingHand-main/Demo/out` (the dora log directory)

5. **Restores the default port** (`--serialport /dev/ttyACM0`), removing this machine's serial port residue

> After cleanup you can copy the whole `AmazingHand-main` folder to someone else — clean and portable. On a new machine, just run 1 → 2 → 3 → 4 in order.

## Linux and macOS differences

The one-click scripts are also available for Linux and macOS, in `AmazingHand-main/Demo/Linux_Deploy_Scripts/` and `AmazingHand-main/Demo/Mac_Deploy_Scripts/` respectively. Steps 1–4 are the same process as on Windows; only the system differences are listed below.

### Script execution permission (Linux / macOS)

After copying from Windows or extracting from an archive, the scripts lose their `+x` execute bit, so run this before the first use:

```bash
cd "AmazingHand-main/Demo/Linux_Deploy_Scripts"   # on macOS use Mac_Deploy_Scripts
chmod +x *.sh
```

After that run them with `./script-name`; do not use `bash script-name`, or the interactive prompts inside the script will be skipped.

### Linux (Ubuntu)

- **Serial port permissions**: `sudo usermod -aG dialout $USER`, then log out and back in; temporarily you can use `sudo chmod 666 /dev/ttyACM*`.
- **Device names**: `/dev/ttyUSB*` (CH340 / CP2102) or `/dev/ttyACM*` (onboard USB serial).
- **Camera**: Settings → Privacy → Camera, allow apps to access it; make sure no other program is using the camera.
- **Virtual machine**: connect the USB camera to the VM first; if OpenCV reports `can't open camera by index` or `select() timeout`, switch the USB controller between 2.0 / 3.1 in the VM settings and restart; if necessary, `sudo usermod -aG video $USER`.
- **Chinese paths**: keep the project path in English characters as far as possible, to avoid MuJoCo / MediaPipe failing to load models.

![Linux one-click deployment](../../assets/robot-arms/amazing-hand/gesture-tracking/ubuntu.png)

![Example of the default serial port in main.rs on Linux](../../assets/robot-arms/amazing-hand/AmazingHand-Official-Example/21.png)

### macOS

- **Serial port**: use `/dev/cu.*`, not `/dev/tty.*`; list device names with `ls /dev/cu.*`.
- **Serial port permissions**: `sudo chmod 666 /dev/cu.usbmodem*`, or allow the terminal in "System Settings → Privacy & Security → Input Monitoring".
- **Camera**: allow the terminal to access the camera on first run; you can also change it in "System Settings → Privacy & Security → Camera".
- **Apple Silicon**: it is normal for the first `cargo build` of the dora dependencies to be slow; if it says "cannot verify the developer", click "Open Anyway" in "Privacy & Security".

![macOS one-click deployment](../../assets/robot-arms/amazing-hand/gesture-tracking/macos.png)

## Manual installation (without the one-click scripts)

If the scripts are not usable, you can deploy manually as described in the official demo:

1. **Get the code**: clone the repository or download `AmazingHand.zip`, and enter `AmazingHand-main/Demo/`.

   ![Demo folder structure](../../assets/robot-arms/amazing-hand/AmazingHand-Official-Example/20.png)
2. **Install the environment**: Rust (rustup), uv, dora-cli; reopen PowerShell/Bash so PATH takes effect. For installation details, see [Environment setup (Script 1)](#environment-setup-script-1) above.
3. **Create the environment and install the dependencies**:

   ```bash
   uv venv --python 3.12
   # Windows: .venv\Scripts\activate
   # Linux/macOS: source .venv/bin/activate

   cd AHControl
   cargo build --release
   cd ..
   cd AHSimulation
   uv sync
   cd ..
   cd HandTracking
   uv sync
   cd ..
   ```

   ![Building the Python node dependencies](../../assets/robot-arms/amazing-hand/AmazingHand-Official-Example/2.png)
4. **Configure the serial port**: edit `--serialport` in `dataflow_tracking_real_right.yml` / `_left.yml` / `_2hands.yml`, changing it to the actual COM port or `/dev/ttyUSB0`, `/dev/cu.usbserial-*`.

   ![Serial port configuration in the dataflow](../../assets/robot-arms/amazing-hand/AmazingHand-Official-Example/19.png)

   ![Default serial port in main.rs](../../assets/robot-arms/amazing-hand/AmazingHand-Official-Example/18.png)
5. **Build and run**:

   ```bash
   # Simulation
   dora build dataflow_tracking_simu.yml --uv
   dora run dataflow_tracking_simu.yml --uv

   # Real hardware (right hand; for left/both, substitute the file name)
   dora build dataflow_tracking_real_right.yml --uv
   dora run dataflow_tracking_real_right.yml --uv

   # Simple angle example
   dora build dataflow_angle_simu.yml --uv
   dora run dataflow_angle_simu.yml --uv
   ```

   ![Building and starting the real-hardware dataflow](../../assets/robot-arms/amazing-hand/AmazingHand-Official-Example/1.png)

   ![MuJoCo simulation and camera tracking windows](../../assets/robot-arms/amazing-hand/AmazingHand-Official-Example/4.png)

6. **FAQ**: mediapipe must be `0.10.14` (Python 3.12); if the dora version is incompatible, align it with `pyproject.toml`/the logs; if OpenCV is missing, install `opencv-contrib-python`; camera permissions, VM USB passthrough and Chinese paths all affect model loading. For detailed troubleshooting, see [FAQ and notes](#faq-and-notes).

> For more detailed official demo documentation, see [`AmazingHand-main/Demo/README.md`](../../../AmazingHand-main/Demo/README.md); the one-click deployment steps for each system have been merged into this page.

## Code structure

### Demo folder

```text
AmazingHand-main/Demo/
├── AHControl/                Rust node: serial control of the servos; config/ holds servo IDs and offsets
├── AHSimulation/             Python node: MuJoCo simulation and inverse kinematics
├── HandTracking/             Python node: MediaPipe hand landmark detection
├── dataflow_*.yml            dora dataflow orchestration
├── Windows_Deploy_Scripts/   Windows one-click deployment scripts
├── Linux_Deploy_Scripts/     Linux one-click deployment scripts
├── Mac_Deploy_Scripts/       macOS one-click deployment scripts
└── docs/                     Official multilingual deployment tutorials
```

### dataflow mapping

| Dataflow file | Purpose |
|------------|------|
| `dataflow_tracking_simu.yml` | Camera gesture tracking; drives only the MuJoCo simulated hand |
| `dataflow_tracking_real_right.yml` | Camera gesture tracking; drives the real right hand |
| `dataflow_tracking_real_left.yml` | Camera gesture tracking; drives the real left hand |
| `dataflow_tracking_real_2hands.yml` | Camera gesture tracking; drives both hands at once |
| `dataflow_angle_simu.yml` | Joint angles given directly; validates the simulation and inverse kinematics |

### Dataflow principle

```bash
Camera → HandTracking (MediaPipe gesture recognition)
              ↓ hand landmark coordinates
         AHSimulation (MuJoCo simulation + inverse kinematics)
              ↓ joint target angles
         AHControl (serial → servo driver board → dexterous hand)
```

### Port configuration locations

- The `args:` line of the three `dataflow_tracking_real_*.yml` files: `--serialport COMxx`

- `default_value = "COMxx"` in `AHControl\src\main.rs` (the serialport argument default)

- `AHControl\config\*.toml`: servo model, IDs, offsets (usually no change needed)

## FAQ and notes

### 1. cargo stuck at `Updating 'tuna' index`

- Cause: the mirror is configured in **git-repo mode** (`.../git/crates.io-index.git`), which downloads a 1GB+ index the first time

- Fix: change `C:\Users\<your username>\.cargo\config.toml` to the **sparse index** (see "cargo Tsinghua mirror settings" above), or simply re-run `1-Install_Env.bat`

### 2. mediapipe missing the solutions submodule / broken install

```bash
uv pip uninstall mediapipe
```

```bash
uv pip install mediapipe==0.10.14
```

- Must be run with the virtual environment activated (in the `Demo` directory)

- `3-Deploy_Demo.bat` already does this as a fallback

### 3. dora version incompatible (message v0.8.0 vs v0.7.0)

![Error log for the dora message format version mismatch](../../assets/robot-arms/amazing-hand/AmazingHand-Official-Example/5.png)

- Symptom: `version mismatch: message format v0.8.0 is not compatible with expected message format v0.7.0`

- Cause: the dora-cli version does not match dora-node-api. **Both must be 0.5.0**

    - Check: `dora --version` should output `dora-cli 0.5.0`, `dora-message: 0.8.0`

    - Fix: `cargo install dora-cli --version 0.5.0 --force`

    - If PATH contains multiple dora installations (e.g. an old version in `C:\Users\<username>\.dora\bin`), make sure `.cargo\bin` comes first, or delete the old version

    ![Old dora dependency packages in the cargo registry](../../assets/robot-arms/amazing-hand/AmazingHand-Official-Example/6.png)

    ![Unified dora dependency version in Cargo.toml](../../assets/robot-arms/amazing-hand/AmazingHand-Official-Example/7.png)

### 4. MuJoCo / mediapipe fail to load models (Chinese paths)

- Symptom: `ParseXML: Error opening file '...\scene.xml'` or `Can't find file: ....tflite`

- Cause: the MuJoCo 3.x / mediapipe C++ loaders on Windows **cannot open absolute paths containing Chinese characters** (e.g. `D:\中文目录...`)

- This project already includes fixes:

    - `AHSimulation\AHSimulation\mj_mink_*.py` switches the working directory before loading models

    - `HandTracking\mediapipe_patch.py` works around it with 8.3 short paths + relative paths

- Do not delete these fix files

### 5. Camera permission

- On first run, choose "Allow" in the popup

- Settings → Privacy → Camera → allow desktop apps to access

  ![Windows camera settings: select a camera](../../assets/robot-arms/amazing-hand/AmazingHand-Official-Example/9.png)

  ![Windows camera settings: basic options](../../assets/robot-arms/amazing-hand/AmazingHand-Official-Example/10.png)

  ![Windows camera settings: allow multiple apps to use the camera](../../assets/robot-arms/amazing-hand/AmazingHand-Official-Example/11.png)

### 6. Port number changes every time

- The COM number may change after replugging USB; re-run `2-Setup_Serial.bat`

### 7. Missing OpenCV

![Error log for the missing cv2 module](../../assets/robot-arms/amazing-hand/AmazingHand-Official-Example/8.png)

```bash
python -m pip install opencv-contrib-python numpy mediapipe -i https://mirrors.aliyun.com/pypi/simple/
```

(run in the `HandTracking` directory with the virtual environment activated)
